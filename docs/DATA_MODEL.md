# Data Model

## Service

A Service record identifies a resource HEARTBEAT is configured to monitor and defines how HEARTBEAT should check it.

id is a unique identifier generated by HEARTBEAT for each Service. It cannot be edited and remains stable across checks and changes to the Service’s other fields.

name is the human-readable name of the Service, such as “Moodle.” The operator may update it if the service is renamed, without changing the Service’s id. It is required and cannot be empty.

url is the web address used to access the Service. The project operator selects and may update it. It is required and must have a valid URL structure.

check_type specifies the monitoring method HEARTBEAT should use for the Service. The project operator selects and may update it. It is required and must be a supported value. The initial supported values will be defined in the first implementation ticket.

A Service describes what HEARTBEAT is configured to monitor. Response time, HTTP status, and other results may change on every check, so a future HealthCheck will record each observation separately. Keeping those results separate lets HEARTBEAT preserve history instead of overwriting the previous result.
